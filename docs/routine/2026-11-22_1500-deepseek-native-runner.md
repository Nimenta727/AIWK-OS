# 2026-11-22 15:00 — 云端模型改为直接接 DeepSeek API（自带智能体循环）

## 决定
用户决定先不适配官方 CLI，改用 DeepSeek API。因此不再包装 CLI，而是自己实现智能体循环，作为独立进程挂在原有的构建监督器下（复用预算、墙钟、隔离、审批收件箱）。

## 调研
- DeepSeek 官方 API 文档（由抓取代理读取，部分页面被截断/摘要，已在 `docs/AIWS_DEEPSEEK.md` 标注）；同类开源项目（Reasonix、DeepSeekCode）；DeepSeek Harness 桌面端（插件是 Node/Cordis 模块，接口在上游仓库，未读到，故未复用）。
- 关键事实：OpenAI 兼容端点；模型 `deepseek-flash`/`deepseek-v4-pro`（旧名已停用）；带 tools 时历史 `reasoning_content` 必须传回否则 400；`tool_choice` 在思考模式只能 auto/none；工具参数是可能出错/被截断的 JSON 字符串；`usage` 含缓存命中数。

## 改动
- `aiws_deepseek.py`：API 客户端（严格主机、重试规则、错误映射、密钥洗白、大小上限、history 规则）。
- `aiws_secrets.py`：密钥只存私有文件，管道传递，界面只见“已配置/末 4 位”，不能存进工作区。
- `aiws_cloud_agent.py`：智能体循环：固定前缀与排序工具（利于缓存）、工具平面执行、**同步批准闸门**、结构化计划（`plan_propose`/`plan_update`，需你批准后才动手）、子智能体（`agent_spawn`，只读为默认、不能再派、最多 8 个）、截断 JSON 修复、旧工具结果压缩、预算/轮次/时间限制。没有 shell。
- 接入：授权令牌支持 `deepseek`（仅 runner 自带工具名、模型/思考/强度/先批计划）；`NativeAdapter`；监督器经 stdin 传任务与密钥、同步批准（拒绝只拒这一步，运行继续；超时才终止）、结果库、计划状态；`/api/v1/cloud/key`；出口白名单加 `api.deepseek.com`；事件 agent 新增 `deepseek`；树页识别 `agent.spawn`。
- 前端：构建页（提供方/模型/思考/强度/允许的操作/密钥面板/最近结果）、计划页对“等你批准的计划”给批准/驳回、总览收件箱按“是否终止运行”显示准确按钮文案。双语，翻译表补充。
- 文档：`docs/AIWS_DEEPSEEK.md`；`docs/AIWS_CLOUD_CONNECTION.md` 加更新说明；CHANGELOG。

## 验证
- Python 全量 635 项通过；前端 45 项、`tsc`、`vite build` 通过。新增：客户端 21、循环 32、监督器端到端 20（真实监督器 + 真实 runner 子进程 + **合成的**假 DeepSeek 服务器）、密钥 8。
- 假服务器**复现了文档里的规则**（缺 reasoning_content → 400、思考模式下 required tool_choice → 400、缓存命中数、429/402 等），所以循环漏传会在测试里失败。
- **变异检查**：故意让监督器总是发“批准”，拒绝类测试随即失败，已还原。
- 端到端覆盖：密钥不出现在 argv/环境/事件库/计划库/结果库/运行记录；删除在批准前不执行；拒绝后不执行且运行继续；无人应答超时终止且不执行；等待时间不计入时限；计划批准/驳回；子智能体树数据；预算由监督器独立执行；用户可中途停止。
- 真实 Chromium（API 用夹具模拟）：构建页（中/英）与计划页截图人工看过，英文模式无中文残留。
- **未验证**：从未对真实 DeepSeek 服务发过请求（参数名、400 条件、usage 字段均来自文档摘要）；真机上专用用户/防火墙/代理放行路径；真实 GPU/网络。

## 已知问题 / 限制
- runner 没有 shell，所以**不能跑测试和构建**；建议下一步加受限的 `shell.run`（固定命令、需批准、专用用户）。
- 非流式，界面不逐字显示；不估算金额；一次一个运行；子智能体顺序执行。
- 本地小模型尚未接入（压缩工具结果、摘要答案、预审）。
- 默认不隔离的构建通道里 runner 没有代理环境变量，无网络的客户机中会以“无法连接”结束（文档已说明）。
