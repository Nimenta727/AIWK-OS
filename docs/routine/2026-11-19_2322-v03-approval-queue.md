# 2026-11-19 23:22 +0800 — AIWS V0.3: durable approval and execution queue

## Completed changes

- Introduced a fail-closed capability registry for project read, official interactive CLI, user-confirmed Git worktrees and once-approved Codex read-only jobs. Windows GUI, arbitrary shell, administrator operations, network publishing and generalized file writes remain inaccessible from the AIWS HTTP API.
- Added a SQLite-backed one-time approval center and persisted job queue with explicit pending/approved/denied, queued/running/succeeded/failed/cancelled/interrupted transitions.
- Added a narrowly scoped background Codex CLI adapter using the official `codex exec --sandbox read-only --ephemeral -` stdin interface; Claude Code remains an official interactive CLI session, without a subscription-token proxy.
- Prevented automatic replay of ambiguous running work after restart; added operator-controlled retry via new approval and cancellation of jobs not yet started.
- Added per-workspace OS advisory lock to reject a concurrent second dashboard server.
- Updated Web UI with approval and job history panels, documented Windows/Hyper-V V0.3 upgrade and recovery procedures, and removed the V0.2 unapproved background runner.
- Preserved legacy SQLite task/workflow data and the existing T3-inspired worktree workflow.

## Validation

- 29 local tests passed with `python -W error::ResourceWarning -m unittest discover -s tests -v` on Linux Python 3.13.
- Portable source-only ZIP integrity passed. GitHub Actions Windows and Python-matrix verification is pending after publication.
- Neither official CLI login, actual Hyper-V guest execution nor Windows UI automation was tested in this environment.

## Known limitations

- Only approved single-stage Codex read-only jobs can run in the background; Claude's subscription is accessed through the official interactive program.
- Running subprocess cancellation, Windows GUI automation and signed installer are not yet available.
- Installed project MCP tools may have permissions beyond Codex's read-only sandbox. AIWS itself is not an OS sandbox; run with a non-admin Windows identity and trusted projects.

## Next steps

1. Verify Windows GitHub Actions and perform manual Hyper-V guest acceptance checks with official authenticated CLIs.
2. Add safe process-tree termination and bounded streaming logs (without changing approval semantics).
3. Implement explicit, supported provider adapters for additional capabilities where licensing and account usage policies permit.
4. Develop separately approved Windows UI automation for selected apps and per-action audit trails.
5. Sign/package a Windows installer and implement tested backups, restore, diagnostics, and version upgrade UI.
