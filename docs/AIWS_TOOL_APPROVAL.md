# 工具调用的审批机制（AI 启动程序 / 调用外部工具）

状态：**底层已实现并有测试；数据集 v3 已就绪；真实客户机里的桌面启动与模型提议质量尚未验证。**

## 三类工具

| 类 | 例子 | 谁能触发 | 是否要审批 | 在哪里执行 |
| --- | --- | --- | --- | --- |
| **读取** | `file.read`、`doc.text`、`tools.list`、`ext.rg`、`ext.jq`、`ext.gitlog`、`ext.sqlite` | AI / 你 | 不要（自动） | Agent（沙箱、无网络） |
| **写入** | `file.move`、`file.trash`、服务操作 | AI 提议 → 你批准 | **要**（持久化的审批记录） | Agent |
| **启动** | `app.launch`（终端、浏览器、编辑器…） | AI 提议 → 你批准 | **要** | **工作台桌面启动器**（只有它能访问显示） |

“外部工具”不再是随便拼命令行：每个外部命令是一条**声明**（`os/runtime/aiws_exttools.py`）——参数类型与上限、固定的 argv 模板、超时与输出上限。

## 启动程序的流程

```text
AI/调用方 ──创建阶段 app.launch {id}──▶ 任务图（待批准，approval=0）
你 ──批准（持久化）──▶ 阶段可派发
Agent 执行：started → Broker 校验“正是这个运行中的已批准阶段”（一次性回执）
   └─▶ 工作台启动器（UNIX 套接字，同 UID）
         └─ 只读重新核对：阶段存在 · 状态=running · approval=1 · 参数恰为 {"id": <登记的 gui 程序>} · 本次执行未用过
              └─ 通过 → 按注册表里的固定命令启动（无任何来自请求的参数，环境为白名单）→ 结果写回阶段与审计
```

为什么要启动器：Agent 有私有 /tmp 且无网络，够不到 X11；工作台在你的图形会话里。所以 Agent 只能**请求**，启动器**不信任请求**，自己再验证一遍。

## 已有的保护（均有测试）
- 参数只有一个 `id`，必须是注册表里 `gui` 类、命令固定的条目；`git`、`viewer`、路径、额外参数一律拒绝（任务创建、Broker、启动器三处各验一次）。
- 未批准 / 未运行 / 已完成 / 参数被改 / 重放，启动器都拒绝；找到套接字的进程不能凭空启动程序。
- 启动器不可用时阶段**失败**，不会静默成功。
- 外部读取工具：参数作为独立 argv 元素且放在 `--` 之后（值不能变成选项）；路径限制在工作区（拒绝绝对路径、`..`、符号链接、`.git`）；环境清洗；超时与输出上限；`ext.sqlite` 不用 `sqlite3` 命令行（其 `writefile()` 即使 `-readonly` 也能写文件），而是 Python 只读连接 + 只允许 SELECT 的授权器。

## 明确的限制
- **同 UID 的应用层防护**，不是内核强制隔离；与 Broker 相同。
- **本地模型现在可以提议 `app.launch`**（数据集 v3 已加入样本与留出评测，见 `AIWS_MODEL_FINETUNING_STANDARD.md` §7），但**还没有用 v3 训练过真实模型**，真实质量未知；提议仍然只是一个待批准阶段。
- 工作台 systemd 单元有 `PrivateTmp`，我加了 `BindPaths=-/tmp/.X11-unix` 让它能连到显示；**这是否足够没有在真实客户机里验证**。
- 「工具」侧栏里你亲手点击的启动仍是直接启动（你本人的操作，有限速），不走任务图。
- 读取类外部工具要求镜像里装有 `rg`、`jq`、`git`（均在包清单中）。写入类外部命令（如 `git commit`）框架支持但**没有注册任何一条**，需要逐条评估后再加。
