## 2. 最终产品形态与用户体验

**产品不是聊天客户端，也不是多个完整上游软件的启动器。** 它是一套在 Windows VM 内执行的可解释开发环境：

1. 用户在统一会话中提出任务，选择项目、Agent、授权模式、预算和工作流模板。
2. 工作台展示将传给模型的上下文预览、来源、估算长度及可移除的重复片段；未经明确执行操作不发送请求。
3. 调度器建立 StageRun，指定工作区或隔离 Worktree，启动受支持的官方工具，并记录真实可观测的事件。
4. 文件树、变更集、Git 提交、工具执行与流程节点联动；每条信息说明证据强度和发生时间。
5. 用户逐文件或逐 hunk 审查拟保留的改动；高风险写入、网络发布和系统修改需要独立审批。
6. 最终交付会话摘要、测试结果、Diff、提交及可复查的时间线；模型用量不明时保持未知。

**长期稳定布局（Claude 风格的暖白、克制和低噪声，但不复制品牌 UI）：**
- 左侧：项目、会话、工作流模板、历史与系统健康。
- 中央：对话和可切换的 DAG 工作流画布；可查看每个 Agent 的输入/输出。
- 右侧：阶段检查器、证据、审批、文件详情、上下文预算。
- 底部：可收起的真实终端、事件流、Git Diff 和诊断。
- 文件树、代码地图与 Git 视图可组合显示，不强迫切换页面才能定位一次修改。
- “本地已观察”“官方事件已证实”“推断”“未知”在视觉和数据上明确区分。

## 3. 发布路线：按依赖顺序交付

### V1.3 — Worktree 隔离与 Git 审查基础（P0；第一开发目标）

**目标：** 一个任务的代码修改能在独立工作区中观察、审查和恢复，尽量减少与用户手动修改产生的归因混淆。

交付：
- 为每个任务或 Agent Run 创建受控 Git Worktree，保留明确的源仓库、分支、基线 SHA 与路径映射。
- 新增 Git 事件时间线：阶段起止检查点、提交、文件状态、rename、create、delete 和工作树变化。
- 逐文件 Diff 查看器：行号、hunk 定位、staged/unstaged 差异、可复制的本地证据引用。
- 首版审批为“批准/拒绝单个文件或变更集的保留与后续操作”，而不是假装已有可靠的逐 hunk 写回；hunk 写入另设可靠性门槛。
- 数据结构区分观察来源（Git 快照、进程工具回执、用户声明）、执行者 ID、工作区 ID、时间与置信等级。
- 文件变更不自动追加到模型 prompt；所有 Git 写操作仍需显式确认。

验收：
- 两个任务在隔离 Worktree 中编辑同名文件互不影响；主工作区不被意外修改。
- 阶段中产生提交、重命名、删除、未跟踪文件都能正确显示；HEAD 漂移、rebase 和工作区被外部删除时安全退化。
- 只读预览不修改 Git index；所有变更审查可以在无 AI 调用时完成。
- 注明 Worktree 不是 OS 沙箱，无法凭它证明进程没有访问别的目录。

### V1.4 — 真正的应用内终端与进程生命周期（P0）

交付：
- 基于 Windows ConPTY 的终端会话桥接，前端使用经过许可核查的终端渲染组件（可调研 xterm.js；不复制上游整套 T3 终端服务）。
- 会话创建/附着/关闭、stdin/stdout/stderr 处理、窗口尺寸同步、退出码、心跳和受限输出缓存。
- 明确的“用户终端”和“Agent 工具执行”两条权限通道：用户终端可以由用户输入；Agent 无权凭 UI 字符串执行任意 shell。
- 进程树取消、超时、窗口关闭恢复提示、终端历史的本地脱敏策略。

验收：
- CLI 输出连续可见且不卡 UI；大输出、中文路径/Unicode、终端重设与断线重连可用。
- 关闭 GUI 不会把已结束的进程误报为运行中；中断状态可核对，不自动重复具有副作用的命令。
- 终端与宿主消息协议有请求 ID、超时和限流；WebView2 来源检查不被绕过。

### V1.5 — 统一事件账本和代码修改证据链（P0）

交付：
- 将分散的任务状态、CLI 启动、审批、Git 检查点、工具回执和导入用量统一成可重放的事件格式。
- 标准事件字段：event_id、task_id、stage_run_id、process_run_id、workspace_id、occurred_at、observed_at、source、evidence_type、payload_version、redaction_level。
- 可视化时间线：Prompt 准备 → 审批 → CLI 进程启动 → 模型/工具事件（可观察时）→ 文件变更 → Git Commit → 测试 → 审查。
- “Agent 修改了此文件”仅在隔离运行环境和可核验的工具事件共同支持时才使用；否则标记“阶段期间观察到”。
- 事件去重、重复导入保护、时钟误差容忍、日志轮转和隐私导出。

验收：
- 重启后还原同一事件顺序；重复导入不使 token 倍增；不从缺失日志推断零调用。
- 同时发生人工编辑和 Agent 运行时，不产生虚假的强因果归因。
- 旧 V1.2 快照可迁移；不完整事件显示“证据缺失”。

### V1.6 — 多 Agent 编排和自动交接（P0）

交付：
- 可视化 DAG：串行、并行、条件分支、人工审批和失败处理；节点可编辑、版本化、模板化。
- 适配器接口统一描述 provider、能力、交互模式、授权来源、运行状态、结构化事件可用性、取消支持与安全边界。
- Claude Code/Codex 按各自官方支持方式启动或集成；某一订阅/CLI 不提供受支持的无人值守模式时，维持人机交接，不能隐蔽代理凭据。
- 多 Agent 上下文交接以摘要、文件引用和变更集为主；每次交接必须可预览、可删减、有来源。
- 阶段重试只在明确人工批准后执行；调度器不会静默重放副作用操作。

验收：
- Claude 规划 → Codex 执行 → Claude 复核：流程与每个阶段的真实执行状态一一对应；不支持的自动化路径有明确降级模式。
- 并行任务有资源与 Worktree 隔离，不会因一个失败丢失另一阶段的已保存结果。
- 断电/进程异常后所有阶段可重建为确定状态。

### V1.7 — 请求追踪、Token 优化和上下文策略（P1）

交付：
- 请求内容结构化预览（系统约束、当前任务、文件片段、历史摘要、工具声明），区分可见材料与 CLI 内部未知开销。
- Provider 用量证据适配器：输入、输出、缓存读取/写入、回合、工具事件；不得将预估冒充官方用量或金融成本。
- 去重哈希、变更驱动上下文选择、增量文件引用、历史压缩、重复步骤提醒、用户可选预算阈值。
- 同一任务的“为什么调用、由谁批准、带了什么上下文、使用了多少可证实 token”可视化。
- 缺乏受支持的使用量/预算控制接口时，预算只实现预警或启动前审批，不声称能硬拦截外部 CLI 内部请求。

验收：
- 无模型请求时查看文件、Git、流程图不增加 Token；导入相同用量事件不重复计算。
- 显示“官方实测 / 本地估算 / 未知”三类用量，并有来源说明。
- 通过固定样例衡量上下文缩减比例与完成质量；不预先宣称节省百分比。

### V1.8 — Windows 权限 Broker 和独立执行进程（P0）

交付：
- UI 与执行 Worker 分离，通过版本化、身份验证的本地 IPC 通信，执行进程采用最小权限。
- Capability 列表：只读文件、读取 Git、写入项目、启动指定工具、网络发布、Windows 设置等，默认最小权限。
- 每个高风险工具请求绑定任务、工作区、参数摘要、到期时间和一次性批准；批准与真实执行回执分开记录。
- 在 Hyper-V VM 中测试账号隔离、Windows ACL、受限网络与故障恢复；是否使用独立用户/进程令牌取决于实际 Windows 安全可行性。
- 执行服务不能接收无约束的“命令字符串”，危险动作仍由宿主权限与用户审批共同阻止。

验收：
- 未经许可的越界写入、发布、系统设置操作被拒绝，并记录审计事件。
- 重复审批令牌无效；取消后不误执行；失败不会留下“已成功”的假状态。
- 必须在非管理员 Windows VM 环境做权限测试。无系统级隔离验证之前，不将产品宣传为安全沙箱。

### V1.9 — 项目代码地图和本地分析（P1）

交付：
- 文件/模块/符号树、跨文件引用、依赖关系与最近变更热点；可优先支持一种主流语言并逐步扩展。
- 可使用本地 LSP 或静态索引；索引默认本机运行，避免不必要的远程模型调用。
- 在文件树选中函数 → 查看引用 → 相关测试 → Git 变更 → 所属 Agent 阶段和关联会话。
- 大仓库增量索引、忽略规则、资源配额、敏感文件排除。

验收：
- 索引可中断、可重建，不阻塞 CLI/编辑操作；不扫描被明确排除的文件。
- 源码地图与实际 Git HEAD/工作区状态关联，不显示过期结果为最新。
- 没有模型或联网也能完成基础符号查找。

### V2.0 — 可长期使用的 Windows 稳定发行版（P0）

交付：
- 可重复的 Windows x64 编译、软件包完整性验证、安装/卸载/升级/回滚与本地数据迁移。
- Hyper-V Guest 的真实 GUI 验收；启动、工作区切换、终端、Diff、Agent CLI、审批、故障恢复、DPI/高分屏和多窗口。
- 崩溃恢复、诊断包导出、隐私与日志保留设置、自动更新选项（默认明确告知/可关闭）。
- 发布渠道区分开发预览和稳定版；签名、发行说明、许可证清单和 SBOM；如尚未签名必须清楚提示。
- 性能基准、数据迁移测试、备份恢复演练、安全复审和用户可操作的安装文档。

验收：
- 从干净 Windows VM 可以安装、创建任务、执行经过确认的官方 CLI 工作流、审查代码并导出审计记录。
- 升级时任务数据无损；损坏数据显式报警并保留可复原备份；卸载不会未经用户同意删除项目源码。
- 各阶段 Windows CI 全绿，真实 Hyper-V GUI/权限验收记录完整。未通过任一发布门槛就维持预览版。

## 4. 模块与代码组织目标（渐进式迁移，不一次性推倒）

| 边界 | 推荐职责 | 不应承担 |
| --- | --- | --- |
| Desktop.Shell | WPF EXE、窗口、系统通知、WebView2 生命周期 | 业务规则、Git 命令拼接、模型凭据 |
| Frontend.DesignSystem | 暖白设计令牌、T3 MIT 控件适配、无障碍组件 | 调度器与执行权限 |
| Frontend.Workbench | 对话、DAG、项目树、Diff、终端、请求证据 | 直接访问文件系统或无限制进程调用 |
| Core.Domain | Task/StageRun、审批、状态机、策略 | 特定 Claude/Codex 命令参数 |
| Core.Events | 持久化事件、因果关系、数据迁移与投影 | 擅自把时间相关说成 AI 因果 |
| Core.Git | Git Worktree、快照、变更集和审查 | 用户未批准的 commit/push |
| Core.Providers | 官方 CLI 适配器、能力协商、状态/用量归一 | OAuth 凭据转售、私有协议抓包 |
| Core.Context | 文件/历史摘取、Token 估算、上下文预览 | 静默把整个项目传给模型 |
| Execution.Broker | 权限、一次性审批、Worker IPC、超时取消 | 接受浏览器发来的任意系统命令 |
| Core.Indexing | 本地符号/引用/依赖索引 | 默许向外部发送源码 |

建议将持久化实体逐步整理为 Project、Task、WorkflowDefinition、StageRun、AgentRun、ProcessRun、Workspace、GitCheckpoint、FileChange、ToolOperation、Approval、UsageEvidence、TraceEvent。所有数据都应有稳定 ID、版本号、更新时间和迁移测试。

可视化设计采用同一个事件账本和只读投影，不能让聊天页、Git 页和流程页维护三套互相矛盾的“状态真相”。

## 5. 专业开源平台的拆分迁移规则

| 上游 | 计划迁移/适配 | 源码与许可证处理 |
| --- | --- | --- |
| T3 Code | MIT UI 控件、Diff/项目体验、终端交互模式、Provider 状态展示 | 按组件提取；锁定上游 commit；保留文件级来源、许可和改动记录；逐个去掉原版 RPC/store 依赖 |
| OpenClaw Windows Hub | Windows 能力注册、系统托盘、权限/Worker 边界和运行状态 | 优先单独 .NET 模块；跨 WinUI/WPF 技术边界不能直接粘贴；移植代码需保留 MIT 声明 |
| Kandev | DAG、任务生命周期、调度/失败恢复模式 | AGPL 源码不直接混入 MIT 发行物；只借鉴架构后独立实现，或先完成正式许可审查 |
| Claude Code / Codex | 官方 CLI、结构化事件、可支持的执行和登录流程 | 使用明确公开、可支持的接口；不抓取或转换订阅 OAuth Token |

每个迁移模块必须有：上游地址与 commit、许可证清单、所选文件、删除的依赖、AIWS 适配器、测试、维护责任、替换/撤销方案。对不再维护的旧 WPF 页面和上游完整嵌入入口，应先做引用盘点和兼容迁移，再逐步删除，避免双实现长期漂移。

## 6. 优先级、依赖与建议实施批次

**先完成 V1.3 → V1.4 → V1.5 的可靠性闭环**，然后才具备可信的 V1.6 自动协作。V1.8 安全 Broker 的最小骨架应与 V1.4/V1.5 并行规划；在提供更强执行能力之前必须完成必要的权限隔离，不能等到所有自动化功能上线后才补安全。

| 批次 | 交付候选 | 进入下一批的门槛 |

## 7. 每个版本统一的完成定义（Definition of Done）

一个功能标记为“已完成”，必须同时满足：
1. 源码、操作路径和界面可用，且没有占位按钮伪装成功。
2. 有明确的错误、超时、取消、重启恢复与权限拒绝路径。
3. 单元、集成、迁移/回归测试覆盖成功和失败行为；Windows CI 能重复构建 EXE。
4. 涉及真实 Windows 终端、ACL、Hyper-V、GUI 的功能必须有 VM 实测证据；CI 绿不等于实机验收。
5. 模型用量必须注明官方、估算或未知；记录可观察事件与结论的证据等级。
6. 任何系统写入、Git 发布或非幂等操作必须满足相应审批要求。
7. 迁移的第三方代码带版本和许可证记录；代码审查后删除不再需要的重复实现。
8. 更新 README、对应 docs 设计说明及 docs/routine/YYYY-MM-DD_HHMM-内容简介.md，说明影响文件、验证、风险和下一步计划。
9. 发布说明注明已验证平台、已知限制、是否签名、源码/二进制下载与 CI 链接。

## 8. 质量目标与可测指标（目标，不是当前成绩）

- **安全**：未审批的高风险执行次数应为 0；未经授权的工作区外写入应被 OS/Worker 边界阻止。
- **一致性**：同一 task/stage 的状态投影应一致；重复导入事件不增加计数；恢复无静默数据丢失。
- **性能**：Windows VM 上测量冷启动、打开 1 万文件项目、Diff 展示、终端输出延迟；先记录 V1.2 基线，再确定可行目标。
- **Token**：追踪可证实的实际 token、缓存命中、上下文重复率和交接摘要长度；用相同任务样例比较完成质量，拒绝空口承诺节省比例。
- **UX**：聊天→文件→Diff→执行证据无需丢失当前任务上下文；无障碍键盘操作、高 DPI、中文路径与深色模式可作为验收用例。
- **维护性**：新 UI 不直接拼接 Git/PowerShell 命令；每个集成有 API 版本约定、错误码和独立测试。

## 9. 风险、原则和不做的事

**风险：**
- 官方订阅和 CLI 并不自动等于可代理的第三方无限制 API；自动化依赖官方当期支持的能力。
- 开源组件许可证及跨技术栈依赖繁多；未经许可审核的“大量直接复制”可能损坏分发合规性。
- Git Worktree 只能改善变更隔离，不构成进程安全沙箱；同一 Windows 用户可能访问其他文件。
- 终端/系统工具容易引入不受控执行；必须有独立 worker、审批和审计。
- 真实 token、缓存用量和成本无法从任意外部 CLI 普遍准确获取；数据缺失必须保留未知。
- Windows 构建和实际 Hyper-V UI/权限测试是两回事；必须保留人工验收清单。

**非目标：** 绕过 Claude/ChatGPT 订阅政策、窃取登录令牌、默认管理员运行、自动推送任何仓库、未经确认修改系统设置、在未审查 AGPL 义务前混入 Kandev 代码、凭时间先后武断断言代码作者。
