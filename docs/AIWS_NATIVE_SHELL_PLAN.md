# AI 原生外壳重构：方案与进度（2026-11-21）

依据：用户验收报告与需求（工作台即桌面、可视化只留有实际效果的、插件功能深度内建并由本地模型统一管理、双盘、宿主显卡模型）。
调研：kiosk 合成器（Cage/Openbox）、agent 可观测性产品（Langfuse 等）、小模型工具检索（RAG-MCP arXiv 2505.03275、AgentFlux arXiv 2510.00229）。

## 1. 设计原则
1. **只留回答具体问题的可视化**：每个图必须回答“AI 在做什么 / 卡在哪 / 花了多少 / 改了什么”。3D、办公室场景、皮肤、余额类一律不做。
2. **插件不搬运，只提取功能**：把它们解决的问题做成系统内部模块，由本地模型通过统一的能力索引调用；许可证不明者只参考设计。
3. **小模型永远只看到一小撮工具**（检索后的 6 个左右），而不是几十个。
4. **一切执行仍经 Agent → Broker → 审批**；新增模块只“展示/检索/只读”，写操作有确认。

## 3. 去桌面外壳
会话只剩无边框 Openbox + 全屏 Chromium（`--app --start-fullscreen`）；`xfce4`/panel/appfinder/notifyd 已从包列表删除。网络、显示、输入法、电源在工作台「系统」页完成（`aiws_system.py`：固定 argv、只接受宣告的模式、Wi-Fi 密码走 stdin、电源需确认令牌）。回到工作台：Alt+Tab 或 Super+Home。

## 4. 宿主显卡模型通道（已实现，宿主半边未在真机验证）
`aiws_model_channel.py`：客体在 127.0.0.1:18080 提供与现在相同的接口，经 **一条 virtio-serial 管道**转给宿主；宿主只调用自己机器上的回环 llama-server，**不为客体监听任何端口**。双向白名单路径、1 MiB/4 MiB 上限、单并发、超时；日志只记大小不记内容。宿主端同时支持 Unix 套接字和 Windows 命名管道。

**QEMU 参数示例（需要你在真机验证）**
```
-chardev pipe,id=aiwsmodel,path=...        # Windows 命名管道：\\.\pipe\aiws-model
-device virtio-serial-pci -device virtserialport,chardev=aiwsmodel,name=aiws.model
```
宿主：`python aiws_model_channel.py host --chardev \\.\pipe\aiws-model --upstream http://127.0.0.1:8080`
客体（新增 systemd 单元，**尚未加入镜像**）：`python3 aiws_model_channel.py guest`

**模型建议**：RTX 5070 Ti Laptop（12 GB）+ CUDA ≥ 12.8；7–8B 工具调用型文本模型、4–5 bit 量化；具体型号需用仓库的评测集在宿主上实测后再定。已不再追求“看屏幕点按钮”的 GUI 模型，因为系统操作本来就是结构化接口。

## 5. 未完成（如实）
1. **双盘 / 只读系统盘 / 工作盘 noexec + 快照 / 三用户分离**：只有设计，没有代码。它要把“Live 光盘”改成“安装到两块虚拟盘”，涉及安装器、分区、dm-verity 或签名校验、挂载选项，必须在真实镜像上迭代，不宜在无法启动镜像的环境里盲写。
2. **规划器接入能力索引**：`/api/v1/capabilities?q=` 已可用，但本地模型的提示词还没有改成只展示检索结果；改提示词会影响模型评测的留出集门槛，需要重跑评测。
3. **客体侧的模型通道单元与启动脚本接线**、宿主侧启动脚本。
4. **输入法实测**（能否打出中文）、无边框全屏行为、菜单超时 hook 与 live-build 实际文件是否匹配：都要启动镜像才能验证。
5. 观察台与文件视图的**真实浏览器视觉检查**（本轮环境里服务拒绝以 root 运行，我没有绕过这条保护去截图）。
6. 默认“按任务/产物/上下文”的文件视图：现在只有“变更审查”和资源管理器两层，按任务组织需要任务引擎记录“任务触及了哪些文件”。
