# 观察台总体方案：用自然语言构建项目，你只负责看

**状态：方案，未实现。** 记录 2026-11-21 与用户确认的方向。依赖真实 CLI、真实 2B 模型、真实客体网络规则的部分均为 NOT VERIFIED，见第 10 节。

## 1. 定位（最重要的四句话）
1. 你只用自然语言说想要什么；系统自己把项目做出来；你在可视化界面里看它工作。
2. **云端模型（通过官方 CLI）做重活**：整体项目构建、写代码、设计。
3. **本地小模型做中转和日常**：理解自然语言、基础文件操作、系统操作、把大任务整理成小上下文。
4. **工作台主界面 = 观察台**。现有的文件管理、DAG、日志、模型请求细节全部保留，但收进“高级”抽屉，只在你想看时打开。

## 2. 总体结构
```
你 ──自然语言──▶ 本地小模型（路由 + 整理上下文，省 token）
                    │ 规则能处理的不调模型
                    ├─ 本机文件/系统操作 ──▶ Agent ▶ Broker ▶ 工具（现有，写操作需批准）
                    └─ 项目构建 ──▶ 授权令牌（Mandate）▶ 监督器（Supervisor）
                                         └─▶ 官方 CLI（独立用户、限域名联网、仅项目目录）
                                                │ 结构化事件流
观察台 ◀── 事件存储（追加式 JSONL + SQLite 汇总）◀────┘
```

## 3. 网络策略：按进程限制（用户决定：不必整机离线）
| 进程 | 网络能力 | 实现 |
| --- | --- | --- |
| **本地模型服务** | 仅 127.0.0.1，**无任何外联** | systemd `IPAddressDeny=any`+`IPAddressAllow=localhost`（已有）；`--host 127.0.0.1`；模型只“提议”，工具由 Agent 执行 |
| Workbench / Agent / Broker | 仅回环与 Unix 套接字 | 现有 |
| **构建通道（官方 CLI）** | 仅放行官方域名 | 独立系统用户 + nftables `meta skuid` 规则只允许连到本机“域名白名单代理”；CLI 经 `HTTPS_PROXY` 走代理；代理只转发白名单域名 |
| 其余 | 默认不放行 | — |
- 不用“按 IP 放行域名”：CDN 的 IP 会变，必须走域名白名单代理。
- 给 CLI **单独的 UID**，才能让 nftables 的 UID 规则成为内核级硬约束（现有 Agent/Broker 同 UID 的弱点不适用于它）。
- 保留两个配置档：**离线档**（默认，CI 的无网络测试仍成立）与**构建档**（开启上述通道）。
- 取舍：比“单独构建虚拟机”弱——CLI 与主客户机同内核；用独立 UID、项目目录隔离、最小权限来补偿。远期可升级为独立虚拟机。

## 4. 授权令牌（Mandate）：一次授权，范围内自动，超出才问你
```json
{"provider":"claude|codex","projectDir":"projects/app1","allowedTools":["Read","Edit","Bash(npm test)"],
 "permissionMode":"...","maxTurns":40,"tokenBudget":{"input":2000000,"output":300000},
 "wallClockMinutes":90,"needApprovalFor":["delete","install-dependency","git-push"],"expires":"..."}
```
- 由**监督器在 CLI 外部**执行：超 token/时长/轮数 → 终止进程并停下来问你；越出项目目录或触发 `needApprovalFor` → 暂停等你批准。
- 受限类别（联网下载任意地址、shell/root 提权、宿主机、永久删除、绕过审批/审计）**任何令牌都不能放行**。
- 令牌本身写入审计；CLI 的登录凭据由 CLI 自己管，AIWS 不读取、不转存。

## 5. CLI 适配器：包起来、读出来
- Claude Code：`claude -p … --output-format stream-json`（官方文档：https://code.claude.com/docs/en/headless ）。Codex：`codex exec --json`（https://developers.openai.com/codex/noninteractive ）。
- **字段格式未经真机验证**（不同来源对 token 字段说法不一致）。适配器必须宽容：读不到就记 `unknown`，**绝不估算或编造 token**。
- 统一内部事件 `aiws.event.v1`：`{ts, agent, session, kind(start|message|tool|usage|approval|error|end), tool?, status?, tokens{in,out,cacheRead,cacheWrite,source:"reported"|"unknown"}}`。
- 另提供嵌入式终端面板（仓库已有 xterm 组件）：想亲自接管时点开，原样运行交互式 CLI。
- 用 **假 CLI 录制回放**做测试（不联网、不花钱），真机验证作为独立步骤。

## 6. 观察台界面（默认首页只有一屏）
1. **顶栏**：本地模型状态、构建通道状态（空闲/运行/暂停）、预算条（已用/上限）。
2. **Token 面板**：总量与预算燃尽线；按智能体/任务拆分；“来源=未知”明确标灰，不补数。
3. **智能体与任务板**：智能体多时默认**折叠成计数**，失败和等待批准的置顶；展开才看图。（解决“项目计划很难看”）
4. **调用状态条**：当前正在发生什么（工具调用、等待、重试），一行一条，滚动条目有上限。
5. **审计结论**：红黄绿三色 + 三句话；点开才有原始记录与哈希链校验。
6. **“需要你”收件箱**：待批准/越界/超预算，唯一需要点击的地方。
7. **底部自然语言输入框**：唯一入口。
8. **“高级”抽屉**：文件管理器、DAG、日志细节、模型请求细节、路由配置——现有功能原样保留。

## 7. 可视化组件选型（来自 2026-11 的网络调研，结论保守）
- **不嵌入 Langfuse / MLflow / Phoenix**：它们是要跑数据库的服务端，与“省资源”冲突；只借鉴“链路 + 用量”的展示思路（Phoenix 为 Elastic License，非 OSI 开源）。
- **React Flow（@xyflow/react，MIT）**：画智能体/任务图；注意署名要求；自动排版需另配布局库（dagre 等，**许可与体积需核实**）。
- **折线/燃尽图**：优先复用仓库已有手写 SVG 组件；如需库，候选 uPlot / ECharts，**本次调研未能核实，采用前先做许可、体积、离线可用的小实验**。
- 仓库已有可复用组件：`ExecutionAtlas`、`InternalObservatory`、`ExecutionTimeline`、`DagCanvas`、`TerminalPanel`。

## 8. 省 token（系统级要求）
1. 规则/语法能解决的**不调任何模型**（指令栏语法、路由规则已是第一层）。
2. 本地模型把大上下文压成摘要再给云端：文件**名**、diff 摘要、错误片段，而不是整文件。
3. 交接内容只含必要的指令与名称；日志先本地摘要，原文留本地。
4. 提示词前缀保持稳定，便于服务端缓存；不在前缀里放时间戳等易变内容。
5. 预算由监督器强制；超出即停。每个任务显示花费，**从事件里统计，不估算**。
6. 观察台由事件驱动更新，不轮询模型；本地模型结果按指令哈希缓存。
7. 移植仓库已有的 `ContextBudgetPolicy` 思路到 Linux 侧。

## 9. 小模型框架（省资源的具体设计）
- **按需启动、空闲卸载**：socket 激活，首次请求才加载，空闲 N 分钟后退出，释放内存。
- 权重 `mmap`，单并发（`--parallel 1`），上下文从 4096 降到约 2048（提示词本身已很短），评估 KV 缓存量化。
- **约束输出**：用 llama.cpp 的 JSON schema/语法约束生成（**需按所用版本核实参数**），减少无效 JSON 与重试，也缩短输出。
- 固定系统提示词开启前缀缓存；`max_tokens` 随任务类型收紧。
- 规则快速通道：确定性指令、重复指令直接命中，不进模型。
- 度量（真实客体）：冷启动秒数、常驻 RSS、tokens/s、P95；用 v1/v2 评测集做质量回归。

## 11. 已知风险与未决事项
- **计费/条款**：订阅账号用于程序化调用（`claude -p` 等）的规则在 2026 年多次变化，无法确认今日状态；启用前须用户自行核对官方页面。AIWS 不触碰登录凭据。
- 事件字段格式未经真机验证；适配器按“未知即未知”设计。
- 用户级 systemd 的 `IPAddressDeny` 是否生效未实测；nftables 的 UID 规则在客体内是否可用未实测。
- 同内核的构建通道隔离弱于独立虚拟机；远期可升级。
- 多智能体任务板的可读性需要真实多智能体数据做可用性验证。

## 12. O1 实现记录（2026-11-22）
- `os/runtime/aiws_events.py`：`aiws.event.v1` 严格校验；`EventStore`（SQLite，0700，WAL；每会话最多 20000 条事件、超出后计数仍准确；`prune` 限制会话数）。
- `os/runtime/aiws_cli_adapters.py`：`ClaudeStreamAdapter`、`CodexJsonAdapter`（支持 `method/params` 变体）、`replay`。适配器**绝不抛异常**，不认识的事件记为 `unrecognized`，垃圾输入合并限流。
- **token 规则**：只记录提供方上报的数字；没有就 `source=unknown`；从未上报的字段保持 `null`，不显示为 0。用量分三种范围：`delta`（确定增量）、`total`（确定累计，优先）、`turn`（逐轮上报，累计还是增量**未验证**，汇总会标“未验证”）。Claude 同一条消息重复上报的用量按消息 id 去重。
- 事件**不含消息正文**：只存长度、工具名和已脱敏的短摘要（命令行密钥、`Bearer` 令牌被替换）。
- 测试发现并修复：`Authorization: Bearer <令牌>` 的令牌曾在脱敏后泄漏；Codex 未上报的 `cacheWrite` 曾显示为 0。
- 样本在 `os/verify/fixtures/cli/`，README 标明为合成数据。**真实 CLI 的字段名与 token 语义仍需 O6 用真机录制核对。**
