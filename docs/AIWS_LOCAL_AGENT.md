# 本地模型的专用 Agent 接口 / The local model's agent interface

**状态（2026-11-22）：已实现并用真实的 Qwen3.5-9B + 真实 `llama-server` 做过端到端验证；没有在真机/显卡上验证。** 数字都来自仓库里能复现的评测，局限写在最后一节。

本地模型只做它被证明能做好的事：**选档（路由）、读日志、读文件并回答、把"要改动的事"写成提案**。它从不自己改任何东西；改动只能是提案，由你在计划审核区批准后由平台执行。

## 3. 为什么线协议是"受约束的 JSON 动作"，而不是原生工具调用

- 原生 `<tool_call>` 依赖服务端 `--jinja` 的解析，而 llama-server 的聊天接口对 `tool_choice` 没有文档；各家服务端（llama-server、llama-cpp-python、vLLM、Ollama）在这一点上差异最大。
- 结构化输出（`response_format`）是各家共有的最大公约数，评测里 9B 在语法约束下没有出现过一次无法解析的输出。
- 因此客户端 `aiws_llm.LocalLLM` 只用共同字段，并按阶梯降级：`json_schema` → `json_object + schema`（llama.cpp 风格）→ `json_object` → 无；收到 400/422/500 时**按错误文字点名的字段**剥离，而不是盲剥。所有回答在本地**再校验一次**（`aiws_jsonschema`），失败时把精确的错误位置发回模型，修复一次。
- 读取端放宽、执行端严格：`normalise_action` 只修**形状**（真实 9B 在 Python 服务上输出过 `{"type":"call","calls":[…]}`，意图清楚、形状混用；`arguments`↔`args`，`answer`↔`text`，多余的说明字段），**从不替模型补内容**；校验仍是严格的。

动作（每步一个）：`call` 一个只读工具 · `calls` 2–4 个互相独立的只读工具（省一次慢往返）· `skill` 加载技能 · `propose` 提案 · `final` 回答 · `refuse` 拒绝。动作 schema 按**本轮可见的工具**现场生成，没显示的工具连写都写不出来。

## 4. 一个回合怎么走（借鉴并对照成熟 agent）

| 机制 | 成熟实现里的做法 | 我们的做法 |
|---|---|---|
| Thread / Turn / Item | Codex App Server 的会话事件模型 | 线程文件是追加式 JSONL，每个 item 落盘即 fsync；页面轮询同一个文件就是实时视图 |
| 用持久化状态重建请求 | 报告第 9 页："让完整请求能从持久化状态重建" | 下一步的请求**逐字节**由已落盘的 item 重建（测试：重启后请求开头与上次完全一致）；未答复的只读调用在重启后补跑（`recover`） |
| 稳定前缀 | DeepSeek 缓存文档、Codex `client.rs` 的 cache key | 系统提示在技能集合不变时逐字节不变；每轮变化的东西（本轮工具、请求）都放在尾部；`PrefixWatch` 在前缀被改写时指出是第几条消息 |
| 先裁剪工具输出再压缩 | DeepSeek Harness `pruneContent`；报告第 6 页 | 工具输出保留头和尾并写明丢了多少，全文按 sha256 单独存放；上下文超过 75% 时**确定性**地把最旧的工具结果换成占位（保持调用/结果配对）；**不用模型做摘要**（见 `docs/routine/…1032…`） |
| 工具并发 | DeepSeek `executeToolBatch`、Codex `parallel.rs` | 只读工具无写冲突，所以只有一个有界的并行池（最多 4），**按模型给出的顺序提交结果**；写操作根本不是工具，是提案 |
| 四个时间点 | 报告第 2 页：环境就绪 / 首字 / 工具执行 / 验收 | 每个回合记录 `readyMs / firstTokenMs / toolMs / doneMs`，以及步数、调用数、修复次数、缓存命中、前缀变化、压缩、降级项，落盘并进观察台 |
| 技能的渐进披露 | Agent Skills 规范 | 第 1 层：名字+一行描述在系统提示里；第 2 层：模型要时才把正文加载进对话；第 3 层（脚本/参考/资源）**不用，从不执行** |
| 插件 | Claude Code 的目录约定 | 同样的目录（`.claude-plugin/plugin.json`、`skills/`、`commands/`），**只取文字部分**，见第 6 节 |
| 钩子 | Claude Code `hooks.json`（运行命令） | **不运行任何命令**；只提供只会"拒绝"的声明式守卫 |

## 5. 安全不变量（每一条都有测试）

1. 只有工具平面里**只读类**的工具能被调用，而且只能是本轮显示给模型的那些；任何会改动的事只能 `propose`，由 `LocalPlanner.validate_any`（和一次性规划器同一个裁判）校验，批准后才执行。
2. 工具输出被包在 `UNTRUSTED TOOL OUTPUT` 里并限长；提案会记录"提出之前读过哪些文件"。
3. 守卫只能拒绝；路由提示只能升档；技能的 `allowed-tools` 只能让**本来就有**的工具可见；插件不能增加工具、不能运行任何代码。
4. 同一时间只有一个回合（模型服务器一次处理一个请求）；并发的第二个回合被拒绝（409）而不是排队。
5. 全部有界：步数、调用数、秒数、输出大小、线程数、文件大小；路径、线程 id、插件名都严格校验。
6. 本地模型关闭时，助手拒绝启动回合，且**从不**碰模型；模型不可用时路由给出明确标注的默认值（flash），不假装做了判断。

## 6. 技能、命令与插件

- **技能**：`<名字>/SKILL.md`（Agent Skills 格式：`name`、`description` ≤1024、`license`、`allowed-tools`……）；也读旧的单文件技能。名字小写加连字符；正文超过 6 KiB 的会被列出但不加载进小模型。
- **命令**：`commands/<名字>.md`，`$ARGUMENTS` / `$1..$9` 展开；用户输入 `/插件:命令 参数`（名字唯一时可省略插件前缀）。以 `!` 开头的 shell 行**保持为纯文本，不执行**。
- **守卫**（`aiws.json`）：`{"deny":{"tool":"file.*","path":"secrets/*"},"why":"…"}`。路径先归一化再匹配（`.ENV`、`./.env`、`a/../.env` 都挡得住）。第一方 `aiws-secret-guard` 挡住 `.env`、私钥、凭据文件。
- **路由提示**：`{"pattern":"payment","tier":"pro"}`，只升不降，模式不得含重复分组。
- **信任**：系统插件在只读镜像里，启用要求目录哈希与固定清单一致；**用户插件默认禁用**，启用必须带上用户看过的那个目录哈希，之后任何文件有一个字节变化就自动失效。
- **不支持（会列出并说明原因，从不运行）**：`hooks`、`mcpServers`、`agents`、`bin/`、`scripts/`、输出样式、LSP、工作流……

## 7. 路由：选哪一档，而不是执行

`local`（本机，零云端 token）/ `flash`（便宜、关思考）/ `pro`（v4-pro、开思考）。**只在任务开头选一次**：任务中途换模型会让云端的提示词缓存整段作废，并丢掉属于另一个模型的推理链；子智能体有自己的上下文，才可以另选。

决策：本地 9B 按**有判定顺序**的提示词判档 → 规则只能**升档**（代码块、堆栈、"死锁/架构/迁移/漏洞"等明确标记）→ 把决定、原因（中英文）和"这需要你批准"之类提示给你，一键可改，**被你改过的次数被记录**。

| 评测集 | 提示词 A（定义式） | 提示词 B（判定顺序，已上线） |
|---|---|---|
| v1（90，调提示词时看过） | 2B 74% · 9B 71% | — |
| 留出集 v2（60） | 2B 70% · 9B 80% | 2B 90% · 9B 96.7% |
| **全新集 v3（45，结果出来前就固定）** | — | **9B 100%（45/45），规则未触发** |

**一个曾经存在、已经修掉的缺陷**：旧的"禁止类别"规则把很多程序员的日常词当成危险请求，并强制留在本地。实测 10 条再普通不过的请求（用 curl 下载、修 ssh 配置解析、`fetch` 封装、解释 `chmod`、上传 S3 ……）全部命中。现在这些规则只**提示**（"这个请求涉及联网，云端智能体做之前会向你申请批准"），**不改变档位**——路由器不是安全边界，授权令牌、批准和路径限制才是。同时收窄了两个误报：`root cause`/`project root` 不再算提权，"安全审计""带审计功能的系统"不再算绕过审计。

## 8. 读日志

`log.digest`（工具平面里的只读工具）：相同模板合并（数字忽略），每条保留**首次出现的行号**和重复次数，原文引用，超预算时优先保留稀有消息；`log.lines` 打开某个行号附近的真实行。模型挑选、人在界面上看到的是**原文和行号**，不是改写。

基准（12 份合成日志，一半的根因藏在 grep 看不见的地方）：9B 12/12，2B 8/12，grep 6/12。

**整栈**（真实工作台 HTTP 服务 + 真实 9B，`POST /assistant/turn` 再轮询）：读一份 C 编译日志，回答"`src/net/conn.c` 里 `epoll_pwait2` 隐式声明导致第 486 行 make 失败"，引用第 485、486 行——这份日志的标准答案正是 [485, 486]；一次移动请求变成计划审核区里一条 `file.move`（中风险、需批准），文件未动；观察台里有对应的本地 agent 会话。

**真实验证发现并修掉的问题**（单元测试都看不到）：

1. **模型门会拒绝 agent 的请求**：门只允许 system/user 两种角色、最多 8 条消息、不允许 `chat_template_kwargs`、不允许流式，转发超时 180 s。已放宽到 agent 需要的程度（允许 assistant 轮次，64 条/12 万字符，`chat_template_kwargs` 只接受 `{"enable_thinking": 布尔}`，超时可配置默认 600 s，流式仍然拒绝），并写了"真实的门 + 脚本化子进程 + 真实 agent"的集成测试。
2. **`log.lines` 的行号被填成整条日志文本**（模型把摘要里的 `L352 WARN free space…` 整行当作 `start`）：行号参数在 schema 里限定为纯数字，读取端也容忍 `L352`/`line 352`。读日志从 6 步降到 4 步。
3. **工具检索对中文几乎检索不到任何工具**，对 `what is in notes.txt` 这种释义式说法也找不到 `file.read`：给每个工具加了中英文同义词、固定显示 4 个基础只读工具、设了最低相关度。
4. **旧的"禁止类别"把大量程序员日常词当成危险请求**（见第 7 节），以及 `root cause`、`安全审计` 的误报。
5. **守卫路径归一化用了 `lstrip("./")`，把 `.env` 变成 `env`，点开头的秘密文件正好绕过守卫**（已修并测试 `.ENV`、`./.env`、`a/../.env`）。
6. **启动守卫的内存估计偏乐观**（7 GiB），实测 `llama-server` 常驻 10.2–10.7 GB，已改为权重 + 5 GiB，服务单元 `MemoryMax` 改为 12 G。
7. 真实的 `llama_cpp.server`（Python）**不按 oneOf schema 约束解码**，真实 9B 在它上面输出了 `call`/`calls` 混用的形状；`llama-server` 本体没有这个问题。已加"读取端放宽、执行端严格"的归一化。
8. 一个已有的偶发失败测试（超大请求时客户端撞上服务端提前断开的 BrokenPipe）。

## 10. 已知局限（如实）

- 没有在真机、没有在显卡上跑过；CPU 上每个回合要几分钟。显卡延迟、7–9B 之外的模型、多槽并发都没测。
- 评测题与日志是合成的，由写规则的同一个人写；路由 45 条、日志 12 条、端到端 9 个场景，单次、温度 0：说明"能工作"，不说明"多可靠"。
- `llama-server` 是在本环境用 PyPI 源码包里捎带的 llama.cpp（a956a85）自己编的，与镜像里固定的提交（`29b52d39…`）可能不同；镜像里那个版本的 `json_schema`、`timings`、前缀缓存行为未验证。
- 第 2 节中"前缀缓存命中"只验证了追加式对话；压缩发生那一刻缓存必然丢失（会被 `PrefixWatch` 报出）。
- 规划器（一次性）的 held-out 门槛尚未在 9B 上重跑。
- **真实的模型门没有和真实的 9B 一起跑过**：门拒绝以 root 运行，我没有绕过这条保护；门的代码用脚本化子进程做了集成测试，9B 用 `llama-server` 直连做了验证，两半协议相同但没有拼在一起跑。
- 第 9 节的 s8 里，守卫没有被真实模型触发（它自己拒绝了）；守卫在整个栈上的行为由 `test_assistant.py`、`test_skills_plugins.py` 覆盖。
- 技能与插件的"命令"只在本地助手里展开；云端构建页不读它们。
